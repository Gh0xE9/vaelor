Kali 工具箱（Docker / WSL） ​

军团的内网攻击能力依赖工具箱 —— 军团在工具箱内执行 nmap、nc 等内网命令，武器库与主程序隔离运行。

平台提供两套工具箱，可并存：

工具箱依赖适用
Kali Docker 工具箱Docker Desktop容器化 Kali 武器库，隔离最彻底
WSL 工具箱Windows WSL2无需 Docker 的轻量替代

Kali Docker 工具箱 ​

前置条件 ​

  • 已安装 Docker Desktop
  • 已获得 Kali 工具箱部署包（随发行包提供，或与 Gh0xE9 联系获取）

启动 ​

在工具箱部署包目录中执行：

bash
docker compose up -d

在桌面端配置 ​

打开 系统配置 → 智能体 → 执行环境 → Kali Docker 工具箱：

配置项说明
模式自动（本机缺少命令时转发到容器）/ 一律走容器 / 关闭
容器名留空使用工具箱默认容器
工作区挂载路径留空则使用数据目录旁的工作区

设置页会显示实际生效的工作区；不在默认位置时，按提示调整挂载卷。

验证 ​

设置页点**「测试连接」**，看到连通即为就绪。

WSL 工具箱 ​

无需 Docker，直接使用本机 WSL2 发行版执行命令：

  1. Windows 上启用 WSL2 并安装 Ubuntu-22.04（或任选发行版）
  2. 打开 系统配置 → 智能体 → 执行环境 → WSL 工具箱，配置发行版名称、挂载根路径与模式
  3. 点**「测试连接」**验证

执行隔离档位 ​

工具箱是否被使用，由执行隔离档位决定：

档位行为
不隔离命令在本机执行
优先隔离（默认）有可用容器 / WSL 就进隔离环境，否则本机执行
必须隔离没有可用隔离环境即拒绝执行，不会回落本机

建议

装好工具箱就保持「优先隔离」；希望命令绝不碰宿主机的场景选「必须隔离」，代价是工具箱不可用时命令会直接报错。 自动模式最省心：本机没有的命令自动转发工具箱，已有的本地跑。
